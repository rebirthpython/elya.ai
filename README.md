# Эля — персональный ИИ-ассистент в Telegram

Бот для одного пользователя: естественный диалог на русском с учётом контекста, история
переписки сохраняется между перезапусками, доступ только по Telegram ID.

**Текущий статус: этап 1 (MVP).** Работают: `/start`, `/help`, `/clear`, `/cancel`, диалог с ИИ,
история в SQLite, ограничение доступа, лимиты запросов, фолбэк между моделями и провайдерами,
индикатор «печатает…», разбиение длинных ответов.

## AI-провайдер

Бот работает с любым **OpenAI-совместимым** API (`POST /chat/completions`) через HTTPX,
без SDK конкретных компаний. Провайдеры перечисляются в `AI_PROVIDERS` в порядке приоритета:
если модель упёрлась в лимит или недоступна, бот пробует следующую модель или провайдера.

| Провайдер | Роль | Бесплатный доступ (проверь перед запуском) |
|---|---|---|
| **Google Gemini API** | основной | Бесплатный тариф AI Studio без привязки карты, но только для моделей Flash / Flash-Lite. Лимиты считаются на проект и периодически меняются: [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) |
| OpenRouter | резерв | Модели с суффиксом `:free`: около 20 запросов в минуту и 50 в сутки, после разовой покупки кредитов на $10 — 1000 в сутки. Неудачные запросы тоже расходуют лимит: [limits](https://openrouter.ai/docs/api-reference/limits) |
| Groq, Ollama, другие | опционально | `GROQ_*` или `CUSTOM_*` в `.env` |

⚠️ Важно:
- **Регион.** Gemini API доступен не во всех странах, в частности не в РФ. Это касается
  страны, где запущен *сервер бота*, а не страны пользователя. Если сервер в неподдерживаемой
  стране, бот запишет в лог ошибку региона и переключится на резервного провайдера.
- **Приватность.** На бесплатных тарифах провайдеры могут использовать запросы для улучшения
  моделей. Бот предупреждает об этом в `/start`.

## Быстрый старт

Нужен Python 3.12+.

1. Создай бота у [@BotFather](https://t.me/BotFather) и скопируй токен.
2. Узнай свой Telegram ID у [@userinfobot](https://t.me/userinfobot).
3. Получи ключ Gemini: <https://aistudio.google.com/apikey>. Можно дополнительно получить
   резервный ключ OpenRouter: <https://openrouter.ai/keys>.
4. Установи и запусти бота:

```bash
cd elya.ai
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # заполни BOT_TOKEN, ALLOWED_USER_IDS, GEMINI_API_KEY
python main.py
```

Если всё в порядке, в логе появится строка `Bot @имя_бота started. Providers: gemini[...]`.

## Проверка этапа 1

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `/start` | Приветствие и предупреждение о приватности с названием провайдера |
| 2 | «Привет, меня зовут Аня», затем «Как меня зовут?» | Бот отвечает с учётом предыдущего сообщения |
| 3 | Перезапусти бота (Ctrl+C → `python main.py`) и спроси ещё раз | Контекст сохранился |
| 4 | «Составь подробный план подготовки к экзамену на 2 недели по дням» | Длинный ответ с форматированием, при необходимости разбит на несколько сообщений; пока модель думает, виден статус «печатает…» |
| 5 | Напиши боту с другого аккаунта | Бот молчит, в логе `Access denied for user_id=...` |
| 6 | `/help` | Счётчики сообщений в истории и запросов за сегодня |
| 7 | `/clear` → «Да, очистить» → «Как меня зовут?» | История удалена, бот имя больше не знает |
| 8 | Отправь больше 10 сообщений за минуту | Одно предупреждение о частоте, лишние сообщения игнорируются |
| 9 | Укажи неверный `GEMINI_API_KEY` | Понятное сообщение об ошибке, причина в логе; если настроен резерв, отвечает он |
| 10 | Отправь фото или стикер | Вежливый ответ, что пока бот понимает только текст |

Автотесты (без сети и реальных ключей):

```bash
pip install -r requirements-dev.txt
pytest
```

## Настройки (`.env`)

Все параметры с комментариями перечислены в [`.env.example`](.env.example). Основные:

- `AI_PROVIDERS`: порядок провайдеров, например `gemini,openrouter`.
- `GEMINI_MODELS`, `OPENROUTER_MODELS`: модели через запятую в порядке приоритета.
- `HISTORY_MAX_MESSAGES` / `HISTORY_MAX_CHARS`: сколько истории отправлять модели
  (влияет на расход токенов).
- `RATE_LIMIT_PER_MINUTE`: защита от флуда.
- `DAILY_REQUEST_LIMIT`: защита квоты; учитывается каждая HTTP-попытка, включая фолбэк.

## Сервер и автообновление

Чтобы бот работал круглосуточно и сам обновлялся после каждого `git push`, разверни его на
Linux-сервере с systemd (Ubuntu, Debian и т. п.). Лучше завести для бота отдельного
пользователя и выполнять команды под ним:

```bash
git clone https://github.com/rebirthpython/elya.ai.git
cd elya.ai
cp .env.example .env && nano .env   # заполни BOT_TOKEN, ALLOWED_USER_IDS, GEMINI_API_KEY
deploy/install.sh
```

`install.sh` создаёт `.venv`, проверяет `.env` и регистрирует user-сервисы systemd:

- `elya-bot` — сам бот: стартует вместе с сервером и перезапускается при падении;
- `elya-update.timer` — раз в минуту запускает `deploy/update.sh`.

`update.sh` проверяет, появились ли новые коммиты в ветке, на которой стоит клон
(другую можно задать через `DEPLOY_BRANCH`). Если появились, скрипт:

1. подтягивает их (`git merge --ff-only`; `.env` и история в `data/` не затрагиваются);
2. обновляет зависимости, если изменился `requirements*.txt`;
3. прогоняет тесты;
4. перезапускает бота и 20 секунд следит, что он не упал;
5. если любой шаг не удался, возвращает предыдущую версию и больше не пытается ставить
   этот коммит. Следующий пуш с исправлением поставится как обычно.

| Команда | Что делает |
|---|---|
| `journalctl --user -u elya-update -f` | лог обновлений: что поставилось и почему откатилось |
| `journalctl --user -u elya-bot -f` | лог бота |
| `systemctl --user restart elya-bot` | перезапуск, например после правки `.env` |
| `deploy/update.sh --force` | переустановить последнюю версию, даже отклонённую ранее |
| `systemctl --user disable --now elya-update.timer` | отключить автообновление |

Важно:

- С одним токеном бот может работать только в одном экземпляре. Если запустить его ещё
  и у себя (`python main.py`), Telegram вернёт ошибку `Conflict`.
- Не правь файлы репозитория прямо на сервере: пока такие изменения не закоммичены или не
  убраны (`git stash`), обновление останавливается с ошибкой в логе.
- Если репозиторий станет приватным, серверу понадобится доступ на чтение, например
  [deploy key](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys).
- Правки `update.sh` применяются сами со следующего запуска. Правки `install.sh` (unit-файлы,
  частота проверки `UPDATE_SCHEDULE`, `RUN_TESTS`) вступают в силу после его повторного запуска.

## Структура

```
├── ai/
│   ├── providers/
│   │   ├── base.py              # типы сообщений, иерархия ошибок, интерфейс провайдера
│   │   └── openai_compatible.py # Gemini / OpenRouter / Groq / Ollama через HTTPX
│   ├── client.py                # фолбэк, паузы после 429, дневной лимит
│   ├── context.py               # сборка контекстного окна
│   └── prompts.py               # системный промпт (личность ассистента)
├── bot/
│   ├── handlers/                # commands.py, chat.py, errors.py
│   ├── keyboards/common.py      # inline-кнопки
│   ├── middlewares/             # access.py (Telegram ID), throttling.py
│   └── utils/                   # разбиение текста, Markdown → HTML, отправка
├── config/settings.py           # загрузка и валидация .env
├── database/                    # модели SQLAlchemy, async-движок
├── deploy/
│   ├── install.sh               # установка на сервер: .venv, сервисы systemd
│   └── update.sh                # автообновление из git с тестами и откатом
├── memory/                      # репозиторий истории и менеджер памяти
├── services/usage.py            # счётчик запросов за сутки
├── tests/
└── main.py
```

## Безопасность

- Токены и ключи хранятся только в `.env`, который исключён из git.
- Бот отвечает только пользователям из `ALLOWED_USER_IDS` и только в личных чатах.
- Тексты сообщений не пишутся в логи: в логах только ID, статусы и ошибки провайдеров.
  Параметры SQL в ошибках скрыты.
- Хранится не больше `HISTORY_STORE_LIMIT` сообщений, вся история удаляется командой `/clear`.
- Бот не выполняет код и системные команды из сообщений.
